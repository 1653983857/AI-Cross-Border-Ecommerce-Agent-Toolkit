# 配置计算与局限

## 目标

G = 已到账现金 + 全部已有持仓现值。R = 应急储备 + 近期支出储备；可承担投资风险的金额参考为 max(G-R,0)。优化变量是每基金的目标金额/G、买额/G、卖额/G、交易后的现金/G。交易费从现金中扣，满足严格资金守恒。

最大化所有前瞻情景中最差的近似年化对数增长：

`g_s = mu_s·w + r_cash*c - 0.5*w'Σw - one_off_cost / horizon_years`

其中 mu 已扣持续费用，Σ 是同币种总回报历史计算的年化收缩协方差，one_off_cost 是一次性费用/G。对数增长使用二阶近似，波动大/跳跃/长尾资产会偏离真实效用；保守收益情景不是最差可能收益。目标与模型输入有关，不是数学上证明“未来最赚钱”。不使用事后收益填未来 mu，不把求解器最优值解释成真实胜率。

## 约束与对照

- long-only，不借款；现金 >= R/G。
- 买卖费用、额度、可售份额、暂停状态、准入、单品上限、总换手。
- 穿透暴露 `sum(exposure_i*w_i)<=cap`，不同风险维度可以重叠。
- 每个压力情景：冲击后损失 + 一次性费用 <= 预算；年化波动 <= 用户预算。压力现金收益也计入。
- 高水位可用时，将已发生回撤计入剩余压力预算；已超预算时剩余预算为零并披露，不能保证重新回到高水位。
- 对照当前持有、全现金、风险资产等权、HRP（PyPortfolioOpt）四种方案。用同一检查器报告可行性；约束不合的基准只作研究参照。

使用 CVXPY/CLARABEL 求解凸优化，只有 solver status=optimal 且独立约束残差检查通过才能给可执行计划。optimal_inaccurate 不升级为通过。无可行解时停止金额交易输出并列出约束摘要。协方差采用 80% 样本协方差+20%对角收缩，额外检查正半定性；不是自动拟合出的最优收缩系数。可通过样本外验证调整，不静默数据挖掘。

## 交易与资金

目标金额按产品增量向下取整；不能增加买额来凑整。本期资金/额度肯定达不到最低申购或整手的新增买单，先在优化前禁用。舍入后重新计算费用、现金、风险和集中度，并与可行的不交易方案比较；若舍入后更差或违约，优先回退不交易。无法回退则保留理论目标、将执行状态标为 blocked_rounding_or_sequence，不输出可执行金额；不能为了强行输出交易而改变约束。连续求解器状态 optimal 与离散计划状态 plan_ready 分开报告，不宣称取整后仍全局最优。

完整计划先卖后买。今日买额只使用已经到账、扣保护储备后的现金；默认不把任何卖出收入提前算成可用。待到账阶段单列，用户确认到账后重新估值、费率、额度、风险再运行。报价变化会改变实际份额和费率。禁止把不同批次的线性费率当作精确税务计算。

分批买入是降低时点和行为风险的可选安排，不自动宣称优于一次投入；比较机会成本和费用。引擎不会自动下单、存储券商密钥、创建监控或安排定投。

## 数据与验证

估值数据必须在明确的允许延迟内，历史长度与频率明确，剔除共同缺失日期。历史拟合风险、未来情景风险、模型遗漏风险分别呈现。基金净值延迟和平滑会压低观测波动；对 QDII、债基、非每日交易资产须额外压力情景，不只看历史标准差。

只有纸面/样本外真实检验才能讨论策略效果。单元测试证明资金守恒与约束执行；合成案例证明流程可跑；均不证明预测能力、获利概率或实盘收益。运行环境与参考源码均使用 PyPortfolioOpt 1.6.0；完整环境版本记录在 requirements-lock.txt。
